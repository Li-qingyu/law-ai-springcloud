## 1. 设计理念

### 1.1 核心问题

```
当前AI Agent项目的痛点：
┌─────────────────────────────────────────────────────────────────┐
│  ❌ 每个垂类行业都重新开发一套Agent系统                          │
│  ❌ 工具/能力与业务逻辑强耦合，无法复用                          │
│  ❌ 知识库、记忆系统、权限系统重复建设                           │
│  ❌ 切换行业场景需要大量代码修改                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 设计目标

```
┌─────────────────────────────────────────────────────────────────┐
│                    AI Agent 行业赋能平台                         │
├─────────────────────────────────────────────────────────────────┤
│  🎯  一次搭建框架，多行业复用                                    │
│  🔌  插件化工具接入（MCP协议）                                   │
│  📦  声明式能力定义（Skill YAML）                                │
│  🧠  通用智能基础设施（记忆/知识/权限）                           │
│  🔄  垂类切换只改配置，不改代码                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 核心设计原则

| 原则 | 说明 |
|------|------|
| **关注点分离** | 通用能力与业务逻辑解耦 |
| **配置驱动** | 通过YAML/JSON配置定义行业特性 |
| **协议标准化** | MCP统一工具接入，Skill统一能力定义 |
| **渐进式披露** | 按需暴露能力，降低用户认知负担 |
| **可组合性** | 基础能力可组合成复杂业务流程 |

## 3. 分层架构详解

### 3.1 用户交互层

**职责**: 接收用户输入，展示 Agent 输出

| 组件 | 说明 | 技术建议 |
|------|------|---------|
| Web App | PC端网页应用 | Vue 3 / React |
| Mobile App | 移动端应用 | Flutter / React Native |
| 小程序/公众号 | 微信生态接入 | 原生 / uni-app |
| API/SDK | 第三方系统集成 | RESTful / gRPC |

**关键设计**:
- 统一的会话管理（session_id 贯穿全链路）
- 支持流式输出（SSE / WebSocket）
- 多端会话同步

**Agent 类型定义**:

| Agent 类型 | 职责 | 使用场景 |
|-----------|------|---------|
| Router Agent | 意图识别 + 路由 | 每次请求必经 |
| Worker Agent | 执行具体任务 | 调用工具、查询数据 |
| Planner Agent | 任务拆解规划 | 复杂多步骤任务 |
| Critic Agent | 结果评审优化 | 需要高质量输出时 |
| Human Agent | 人机交互确认 | 敏感操作、意图澄清 |

**Skill YAML 定义规范**:

```yaml
# skills/common/data_query.yaml

name: "data_query"
description: "通用数据查询能力"
version: "1.0.0"
category: "common"  # common | industry_specific

# 触发条件
triggers:
  intent: ["query", "search", "find", "查看", "查询", "搜索"]
  confidence_threshold: 0.7

# 渐进式披露级别
disclosure:
  level: "basic"  # basic | intermediate | advanced
  auto_activate: true  # 是否自动激活
  require_confirm: false  # 是否需要用户确认

# 所需工具（来自MCP）
required_tools:
  - pattern: "mcp://{server}/query_{entity}"
    description: "查询指定类型的数据"

# 输入 schema
input:
  type: object
  properties:
    entity_type:
      type: string
      description: "数据实体类型"
    filters:
      type: object
      description: "过滤条件"
    pagination:
      type: object
      properties:
        page: { type: integer, default: 1 }
        page_size: { type: integer, default: 10 }

# 输出 schema
output:
  type: object
  properties:
    items: { type: array }
    total: { type: integer }

# 执行策略
execution:
  timeout: 30000  # 超时时间(ms)
  retry: 2  # 重试次数
  cache: true  # 是否缓存结果
  cache_ttl: 300  # 缓存时间(秒)
```

```
│     │                                                           │

│     ▼ 用户请求复杂操作                                          │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ Level 2: Intermediate Skills (中级能力)                   │   │
│  │ - 批量操作、数据导出、统计分析                           │   │
│  │ - 需要用户确认后激活                                     │   │
│  └─────────────────────────────────────────────────────────┘   │
│     │                                                           │
│     ▼ 用户请求高级功能                                          │
│  ┌─────────────────────────────────────────────────────────┐   │

│                                                                 │
│  触发判断逻辑:                                                   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ if skill.disclosure.level == "basic":                    │   │
│  │     auto_activate()                                      │   │
│  │ elif skill.disclosure.level == "intermediate":           │   │
│  │     ask_user_confirmation()                              │   │
│  │ elif skill.disclosure.level == "advanced":               │   │
│  │     check_permission() and ask_user_confirmation()       │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 6. 技术选型建议

### 6.1 技术栈推荐

| 层级 | 推荐技术 | 备选方案 | 说明 |
|------|---------|---------|------|
| **网关层** | Spring Cloud Gateway | Kong, Nginx+Lua | Java 生态首选 |
| **Agent 框架** | LangGraph (Python) | AutoGen, CrewAI | 灵活的工作流编排 |
| **LLM** | 通义千问 / DeepSeek | GPT-4, Claude | 国内场景首选国产 |
| **MCP 实现** | 自研 MCP Client | 官方 SDK | 根据语言选择 |
| **向量数据库** | Milvus | Qdrant, Weaviate | 性能好，社区活跃 |
| **缓存** | Redis | Memcached | 功能丰富 |
| **关系数据库** | MySQL | PostgreSQL | 成熟稳定 |
| **对象存储** | 阿里云 OSS | MinIO, S3 | 按需选择 |
| **前端框架** | Vue 3 | React | 国内生态好 |
